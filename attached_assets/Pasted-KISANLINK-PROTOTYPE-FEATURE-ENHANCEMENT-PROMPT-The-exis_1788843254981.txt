4. STRICT LANGUAGE MODE
==================================================

This is VERY IMPORTANT.

When the farmer selects a language during login/registration, the application's user interface and AI interaction should consistently use that selected language.

Supported languages should include at minimum:

- English
- Hindi
- Marathi
- Telugu

Keep the architecture extensible for:

- Tamil
- Kannada
- Bengali
- Gujarati
- Punjabi
- Malayalam
- Urdu

LANGUAGE RULE:

If the farmer selects Telugu:
- UI should be Telugu
- AI responses should be Telugu
- Voice responses should be Telugu
- Buttons, labels, headings, instructions, errors and system messages should be Telugu wherever translated strings are available.

If Hindi is selected:
- UI and AI should be Hindi.

If Marathi is selected:
- UI and AI should be Marathi.

If English is selected:
- UI and AI should be English.

DO NOT MIX ENGLISH INTO THE SELECTED LANGUAGE JUST BECAUSE IT IS EASIER.

For example, do not produce:
"మీ పంట Market లో మంచి Price పొందుతుంది."

Instead, use natural Telugu:
"మీ పంటకు మార్కెట్లో మంచి ధర లభించే అవకాశం ఉంది."

Similarly, Hindi and Marathi responses must remain naturally written in those languages.

IMPORTANT:
- Do not translate the farmer's request into English and then return an English answer.
- The AI should understand multilingual input internally but respond in the farmer's selected language.
- Preserve the selected language throughout the conversation unless the farmer explicitly changes it.
- Mixed-language input such as Hinglish, Telugu-English or Hindi-English should still be understood naturally, but the FINAL RESPONSE must follow the selected language.

Create/use a centralized language configuration/translation system instead of hardcoding language checks throughout the UI.

6. CROP QUALITY CHECK — IMPROVE FRAUD RESISTANCE
==================================================

Current quality checking only asks for pictures.

This creates a potential fraud problem because someone could upload only a carefully selected good-looking image.

Improve the workflow.

Do NOT use only one image.

Require MULTIPLE images for a quality assessment.

Target:
- Minimum: 4 photos
- Recommended: 5 photos
- Maximum: 10 photos

Allow the farmer to capture/upload multiple images from different views.

The UI should guide the farmer to capture different views, for example:

1. Overall crop/produce view
2. Close-up view
3. Side/alternate angle
4. Representative sample
5. Optional additional close-up
6-10. Additional supporting images if required

Do not simply allow the exact same image to be uploaded repeatedly.

Where technically possible:
- Detect duplicate images
- Compare image hashes/visual similarity
- Warn if multiple uploaded images appear identical or nearly identical
- Ask for another image

For the SIH prototype, this can be implemented as a practical anti-fraud measure rather than claiming perfect fraud prevention.

7. CROP QUALITY INPUT DATA
==================================================

Quality should NOT be judged from pictures alone.

Collect additional structured information during the quality-check process.

Ask for relevant information such as:

- Crop/produce type
- Variety if known
- Harvest date
- Approximate age since harvest
- Storage conditions
- Handling information
- Location/district
- Quantity
- Any visible damage
- Whether the produce was recently harvested
- Other crop-specific information where appropriate

Most importantly, capture:

HARVEST DATE

The AI should calculate the approximate number of days since harvest using the current date and harvest date.

Example:

Harvest date: 5 September
Current date: 8 September
Days since harvest: 3 days

Use this information as one of the inputs to the quality assessment.

Do NOT invent harvest dates.

8. AI QUALITY ASSESSMENT
==================================================

The quality assessment should combine:

A. Multiple images
B. Crop/produce type
C. Harvest date
D. Days since harvest
E. Storage conditions
F. Handling information
G. User-provided observations
H. Other relevant structured information

The AI should produce:

- Grade A
- Grade B
- Grade C

Also produce:

- Quality score
- Main observed issues
- Confidence/assessment strength where appropriate
- Recommended next action
- Storage recommendation
- Suggested urgency for selling if relevant

Example output structure:

GRADE A

Quality Score: 91/100

Observed:
- Good appearance
- Minimal visible damage
- Fresh appearance
- Suitable storage condition

Recommendation:
Suitable for premium buyers/traders.

OR:

GRADE B

Quality Score: 72/100

Observed:
- Moderate surface defects
- Some variation in quality
- Freshness reduced compared with Grade A

Recommendation:
Sell to standard market/traders and avoid unnecessary storage.

OR:

GRADE C

Quality Score: 48/100

Observed:
- Significant visible damage
- Reduced freshness
- Quality concerns

Recommendation:
Consider faster sale/local processing where appropriate.

IMPORTANT:

Do not present the AI assessment as a certified scientific laboratory test.

Clearly communicate that the result is an AI-assisted visual/metadata assessment and that actual grading can vary based on professional inspection and market standards.
