Do NOT redesign the application.
Do NOT modify the dashboard design.

Inspect the ENTIRE existing voice pipeline and actually test it.

Microphone
→ Audio recording
→ Server
→ Multilingual Speech-to-Text
→ Language detection / selected-language handling
→ Real LLM
→ Response in the farmer's selected language
→ Multilingual Text-to-Speech
→ Audio returned to browser
→ Audio playback

================================================
1. SPEECH-TO-TEXT
================================================

Use the existing Groq API architecture and multilingual Whisper model if already configured.

Use:
whisper-large-v3

Do NOT use browser SpeechRecognition as the primary speech-to-text system.

The microphone recording must:
- Request microphone permission correctly.
- Record actual microphone audio.
- Produce a valid supported audio format.
- Send the audio blob/file to the server.
- Server must send it to Whisper.
- Return the actual transcription.

Test with:
English
Hindi
Marathi
Telugu
Hinglish / mixed-language speech

Do not assume the browser language is English.

================================================
2. LANGUAGE HANDLING
================================================

The language selected by the farmer during account/login must be preserved throughout the conversation.

If selected language = Telugu:

User speaks Telugu
→ transcription
→ AI understands it
→ AI response MUST be Telugu
→ TTS MUST speak Telugu

Same for:
Hindi
Marathi
English

Do NOT translate the final response into English.

Mixed-language input should still be understood naturally, but the FINAL response must follow the selected language.

Check the entire language pipeline for places where:
- language is hardcoded to English
- locale is hardcoded
- browser speech language is forced to en-US
- TTS defaults to English
- AI system prompt forces English

Remove/fix those problems.

================================================
3. REAL CONVERSATION CONTEXT
================================================

The assistant must remember the current conversation.

Example Telugu conversation:

Farmer:
"నా టమాటాలు అమ్మాలి."

Assistant answers.

Farmer:
"ఈరోజు అమ్మితే ఎలా ఉంటుంది?"

The assistant must understand what "ఈరోజు" refers to from the previous message.

Do NOT use canned responses.

Send conversation history/context to the LLM.

================================================

The biggest current problem is that the AI response is not being played as audio.

Inspect the entire TTS implementation.

Use the existing Gemini API integration if available for multilingual TTS.

The TTS system must support at minimum:

English
Hindi
Marathi
Telugu

The generated audio must:

1. Be generated by the server.
2. Return successfully to the client.
3. Have the correct audio MIME type.
4. Be converted into a browser-playable audio format if necessary.
5. Create an actual Blob/Audio URL on the client.
6. Call audio.play().
7. Handle browser autoplay restrictions.
8. Provide a visible speaker/play button if automatic playback is blocked.

DO NOT merely display:
"Audio generated successfully"

Actually verify that audio playback occurs.
